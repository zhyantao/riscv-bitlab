异常与中断

先解读陷阱原因，再按需补充状态 CSR、通用寄存器现场和逐级 PTE。选择实际接收陷阱的模式；XLEN 指所选陷阱寄存器的宽度。所有计算在本地完成，不上传现场。

原因可从下拉框选择，也可在原因寄存器中填写自定义编码；下拉选择中断时自动设置 XLEN 最高位。原因寄存器必填；epc、tval 和其他现场可留空，表示未知而不是零。支持十进制、0x、0b、0o 及数字间下划线分组（如 0x0000_0001_0000_0000），只接受 XLEN 范围内完整非负整数，切换位宽不截断输入。默认现场留空；可主动加载 example.tc 的 Loop 72 故障示例，缺失字段不补零。

这是基于快照的辅助分析，不是硬件执行记录。 请使用同一次陷阱、同一 hart 的现场。PTE 内存快照可能不同于触发异常时的 TLB / 页表状态，不能仅凭当前映射判定硬件错误。

    故障指令与通用寄存器分析 x0–x31

    填写 trap 入口汇编保存的被中断程序现场，不是 C handler 当前寄存器。x0 固定为 0；空白表示未知。当前自动计算仅支持基础整数 load / store；压缩、AMO、浮点和向量访存需另行分析。

    页故障 · 逐级 PTE 分析

    输入真实 PTE 快照后才向下寻址，遇到缺失即停止。支持 Sv32 / Sv39 / Sv48 / Sv57 及对应 G-stage x4 模式；不模拟两阶段嵌套内存读取。

    SUM / MXR 填访问时的有效值，而不是无条件复制当前 status：VS-stage MXR = HS.MXR OR VS.MXR；G-stage 仅使用 HS.MXR，且按 U 权限检查、不使用 SUM。这里的“写 / AMO”检查页表写权限，不模拟原子访问的其他约束。

    顶部 PTE 输入的寻址结果与原值回显；未采集时停止遍历。
    级别索引与 PTE 寻址PTE 原始值字段与检查结果

    已知条件仅覆盖基础页表规则，不覆盖 PMP / PMA、扩展权限、TLB 陈旧或 SFENCE.VMA / HFENCE 时序。读取 PTE 本身失败不能自动归为页故障，需要区分访问故障和两阶段翻译失败。

    外部证据与平台检查

    下载日志转换脚本下载解析库下载寄存器定义

    三个脚本放同一目录：node parse-trap-log.cjs trap.log --xlen 64 --target M --asm thread3.asm --output evidence.json；多份现场用 --record 1 选择。

    JSON 格式说明与示例

    必填 version=1、xlen、target、registers。所有寄存器、地址和种子使用字符串，空缺字段省略，不用零代替未知。寄存器名使用小写；原日志 STATUS / 非零 X0 使用 log-status / log-x0。source 为来源，instruction 为原始机器码，snapshot 声明采样时点，translation 为一次独立页表遍历，physical 为物理访问证据，notes 保存补充说明。未知字段和超宽数值会报错。
